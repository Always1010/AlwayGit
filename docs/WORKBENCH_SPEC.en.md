# Workbench Specification

[简体中文](WORKBENCH_SPEC.md) | [Project home](../README.md)

This document records confirmed AlwayGit behavior as the reference for implementation, testing, and continued development.

<a id="layout-and-appearance"></a>

## Layout and appearance

The Workbench is AlwayGit's single repository workspace. It opens in an editor tab by default. The Activity Bar icon reveals a lightweight launcher using the VS Code theme, showing the Editor Tab, Primary Sidebar, Secondary Sidebar, and Panel locations, their enabled states, and the default destination. **Open Workbench** states its destination. **Configure display locations and default…** opens the location dialog; the native title-bar gear remains available. The secondary new-window link creates an independent window with no repository selected. The launcher stays in place without appearing automatically as a dialog. Its labels follow the extension language and refresh after configuration changes. Restoring the launcher does not automatically open an editor Workbench. Show focuses the active editor Workbench, otherwise the most recently used one, otherwise a new one, preserving existing tabs, repositories, layouts, and drafts. The status-bar icon remains available and follows the configured default.

The native AlwayGit view-title gear always opens **Workbench Locations**, shared by the launcher and full Workbench. The dialog has four checkboxes and a default-location list containing only enabled locations. Disabling the current default selects the first remaining location. It explains that multiple locations can be enabled simultaneously, with independent state, while opening the Workbench enters only the default. At least one location must remain enabled; otherwise Apply and Open is disabled with an explanation. Apply and Open saves the complete configuration, closes the dialog, restores focus, then opens or focuses the default. A save failure retains the dialog and draft. Cancel, Close, and Escape discard changes. Opening, moving, new-window, and extension-preference actions are separate. The More-menu location entry retains its sidebar icon; the Workbench's Settings gear continues to control interface preferences. Scrolling keeps the dialog's bottom actions reachable in narrow sidebars and short panels.

`alwaygit.workbenchLocations` is a user configuration object. `enabled` accepts one or more of `editor`, `sidebar`, `auxiliary`, and `panel`; `default` must belong to that set. Without configuration, only Editor Tab is enabled. Legacy `alwaygit.openMode` remains compatible when the new setting is absent, retaining old docked sessions. Sidebar directions follow VS Code. Enabling locations does not open all Workbenches at once. Open Workbench, Show, and the status bar enter only the default; explicit commands open individual locations. Applying preserves instance state and creates a missing default instance. Disabled Secondary Sidebar and Panel views hide after their originating dialog closes.

The three docked views can coexist with multiple editor tabs. Repository directories, actual Git state, and interface preferences are shared; repository selection, drafts, history filters, file selection, comparisons, layout, and terminals belong to each instance. The Primary Sidebar launcher stays available. Disabling Secondary Sidebar or Panel hides its view but keeps its session, drafts, and running terminals for reopening. Disabling Editor Tab or Primary Sidebar only limits subsequent opening. VS Code's native move selector can move each independent view among the sidebars and panel; title actions follow the view. Explicit location opening restores the view and its AlwayGit container to their native region before focusing them.

**Copy Current State to a New Editor Tab** requires Editor Tab to be enabled and copies the latest state of the most recently active Workbench: repository, draft, commit selection/comparison, Diff version, and filters. Existing AlwayGit/file tabs, unpinned previews, and the source remain. Terminals stay in the source; the new tab starts on Diff. Failure preserves the source; an active Git operation must finish before copying. The More-menu **New Workbench Tab** retains its split icon and always creates a new tab, inheriting preferences, drafts, and repository list but initially selecting no repository. Its empty session must not overwrite the last repository restored by ordinary Show. Opening a repository through its object menu selects that repository in the new tab.

At widths below 600 px or heights below 440 px, region navigation shows Repositories, History, Details / Changes, or Diff / Terminal one at a time. Regions stay mounted and preserve selections; enlarging restores the parallel layout. The toolbar scrolls internally rather than overflowing the entire Workbench. Editor and docked layout baselines are stored separately.

Before the first repository-catalog response, the sidebar and main area show loading; Add and repeated refresh are disabled. After ten seconds, a slow-loading explanation and log entry appear. Failure offers error details, Retry, and logs. Only a successfully confirmed empty catalog shows the add-repository guide; a restored nonempty catalog with no active repository shows a selection prompt. Later background refresh keeps existing content.

The top toolbar is one row. The left contains the current branch, Fetch, Pull, Push, Commit, Stash, and repository-wide unified-list actions. The fixed right contains Refresh, Settings, and More, with 28 × 28 px hit areas and 16 px icons. Only the left scrolls when space is scarce; region navigation stays separate. More is a single-level menu ordered Locate HEAD, Open Repository Folder, New Workbench Tab, Open Workbench in New Window, Workbench Locations, Restore Layout, Help & Guide. Separators precede the third and sixth entries. Existing 16 × 16 px icons include the folder/VS Code combination; icon/text spacing is 8 px, row height at least 30 px, and width 240 px within the viewport. Existing actions, availability, and shortcuts apply. Menu opening suspends Workbench shortcuts; arrows and Home/End navigate, Escape returns focus to More.

In ample space, Repositories and refs are left, Graph/History center, details/files/Working Tree right, and the shared read-only Diff/terminal dock below. Commit Message uses a separate dialog. There is no layout-mode selector; legacy Editor Focus sessions migrate to Workbench while preserving panel sizes, repository views, and drafts. Native editing and Diff remain available.

Panel separators and Graph, author, and date widths are draggable. Dock maximum height follows available space while preserving a usable top region. It can collapse to its tab strip and recover its former height. Graph uses its right edge; author and date use their own left separators, following pointer direction rather than a hard-to-hit far-right handle. Graph width defaults to 64 px and persists within 48–180 px. Restore Layout retains its layout icon and restores only panel/column dimensions and dock expansion, not preferences. History defaults to 13 px type and 24 px rows, vertically centered, with alternating surfaces and fine dividers. The virtual Working Tree uses a solid diamond, emphasis, counts, and an entry arrow; HEAD uses an ordinary Commit node and branch name, without an extra ring, green row marker, or HEAD badge. Narrow views scroll internally or collapse secondary content.

Unified surface levels cover content, sidebar, headings, and toolbar. Buttons use small radii, borders, and brief hover feedback. The leftmost branch badge shows only its icon and name; repository, upstream, and exceptional status are in its tooltip. There is no permanent bottom status bar: Git feedback appears below the top toolbar, while other useful notices appear as dismissible messages. Successful copying is silent; failures notify. Status, progress, and conflicts remain distinct. Typical headings are about 26 px and buttons about 24 px; file information and operation explanations stay readable, with parent directories shown according to the selected display mode. Section headings have disclosure controls and icon actions; see [sidebar section actions](#sidebar-section-actions). Reduced motion disables transitions and rotation.

Settings is an approximately 760 px dialog with General / Interface / Graph / Advanced groups and separate language, theme, type/density, file-list, Diff, palette, and Git-operation pages. One page shows at a time with its hierarchy. Type/density controls only interface font and history-row density with a row preview. File List controls split/unified display, file path display, and file spacing with a preview. Diff groups display and navigation, previews comparisons, and initially collapses detailed navigation rules. Theme cards follow VS Code light/dark/high contrast or choose clear light, warm paper, mist blue, deep night, midnight blue, graphite, forest, berry purple, or high contrast; each theme defines consistent surfaces, text, borders, and selection.

Interface type supports 12–16 px, Diff 11–18 px (default 12), and history rows 22/24/28 px. File padding defaults to 1 px per side, with 0/1/3/5 px presets and 0–8 px custom values. File names use 1.4 line height; parent paths use 11 px type with 1.2 line height, separated by a 1 px gap without vertical shrinking. At 13 px, default two-line file rows are 36 px across details, comparisons, and Working Tree. Wrapped paths in two-line mode and larger type grow rows. Legacy sessions receive new spacing defaults while keeping other settings. Diff line height defaults to 18 px, offers 18/20/22/24 px presets and 16–36 px custom values, and is at least font size + 4 px. Larger fonts increase minima; virtual rows remeasure while preserving the top reading position.

Changes preview immediately. Apply saves without restarting; Cancel, Close, Escape, or backdrop restore the applied baseline. Background refresh during preview saves applied settings rather than draft preferences. Repository selection, commit drafts, and files are unaffected. Unified lists are the default when no display preference has been saved; existing split or unified preferences remain in effect. Unified lists order Conflicts, Unstaged, Staged, then filenames/full paths; two versions of one path remain separate entries. Unified toolbar Stage All, Unstage All, and Discard All sit between Push and Commit and always target the complete repository, regardless of filters or selection; Discard All discards only unstaged content. Split mode keeps section actions. Current-repository refresh is fixed on the right.

Graph provides vivid 12 colors by default, distinct 8, and extended 16, adapted to light/dark surfaces. Presets are starting points: edit HEX/colors, use 4–16 entries, restore a preset, and independently set light/dark mainline colors. Actual fork/parallel/merge previews indicate whether colors reach 3:1 contrast. The remote default branch, falling back to `main`/`master`, uses a thick mainline; HEAD remains ordinary, identified by branch and accessibility semantics. Colors belong to history paths rather than columns: first parents inherit, and connectors joining an existing parent path retain their source color and hover lineage; other parent connectors use the destination lineage. Only first-parent edges of the default branch use the thick mainline color; side connectors keep their color until they join a mainline ancestor. New paths prefer free colors then perceptual separation in the active palette. Finished paths free slots; exhausted palettes avoid matching adjacent paths where possible but cannot guarantee distinct colors for arbitrarily many active paths.

Known `refs/remotes/*` after the most recent Fetch determine remote reachability: remote-reachable commits use solid nodes and bold messages; local-only commits use smaller hollow nodes and normal weight. Node outlines always use their path color, matching the fill of solid nodes without a foreground-colored border; selection thickens the same-color outline and highlights the row. Merge nodes remain larger; selection and hover coexist with publication status. Finished internal lanes collapse promptly through continuous curves; lane spacing stays at 18 px, with the actual Graph column accommodating all active lanes and edge padding. Wide parallel histories expand the column and scroll within History instead of compressing node spacing or clipping paths. A compact legend appears above History. Git supplies remote status for pages/search; visible ref badges do not establish publication.

Working Tree is a frontend-only virtual commit, excluded from Git commits, history counts, offsets, and bulk commit operations. If HEAD is visible, it is placed immediately above HEAD in newest-first order and moves after Commit, Checkout, Reset, and branch changes. If filters exclude HEAD/current branch, only the independent Working Tree remains, without reinserting or linking to hidden HEAD. It has a persistent teal surface, 3 px left stripe, fine border, matching diamond/ring/current-row connector/file/entry icons, and theme variants. Hover/selection deepen the teal without changing row height or position. Message contains a bold title, secondary change/conflict counts, and branch icon/name; Date says Uncommitted. An unborn repository also has a standalone initial Working Tree.

Click or Enter opens Working Tree; arrows navigate continuously between it and real commits. It does not participate in Ctrl/Cmd/Shift commit selection, double-click Checkout, or the Commit menu. Accessibility exposes its virtual status, branch, change count, uncommitted and selected states. Pagination carries path allocation, palette identity, and cursor. Theme changes preserve color slots; preset/value/count changes rebuild the entire graph rather than joining old-palette pages. Same-order refresh and virtualization preserve colors; filters/ref changes can reassign them. Hovering a path highlights visible segments and dims others. Finite palettes do not promise suitability for every color-vision condition.

<a id="help-and-guide"></a>

## Help & Guide

The question-mark **Help & Guide** entry in More opens the help dialog with matching name, tooltip, and accessible meaning. Empty states with no repository added/selected also offer Quick start. Navigation has Quick start / Common tasks / Common questions / Full manual. Search filters titles and content within the active category and explicitly reports no matches. Full manual displays chapters; internal links enter it and locate sections. Locations, instances, file-list modes, selected-file commits, Tag status, terminals, and shortcut management each have task entries backed by shared manual sections. Escape, backdrop, and Close return focus to the opener.

Help follows Workbench language, theme, and narrow-view layout. Content and shared images come from the [English manual](USER_MANUAL.en.md) and [Chinese manual](USER_MANUAL.zh-CN.md), packaged for offline use; page resources load on first opening and images lazily. Both editions share images, updated only for affected scenes, with each figure's actual capture date and source baseline recorded in the manual. Sample data is not evidence of real Git/host operations. Help state stays in the dialog. Navigation/search do not run Git/native editing, change repositories, drafts, layout, history or Diff, or automatically start tours.

## Selection and opening

The Workbench distinguishes no repositories, no selection, opening, removed/unavailable repositories, ordinary branches, and actual Detached HEAD. Only a loaded repository without a current branch shows Detached HEAD. A new session does not select the first repository automatically; removing the current repository clears that tab's selection instead of switching silently.

Add Repository accepts a repository or parent directory. If the selected directory has `.git`, validate it; otherwise scan all descendant levels for valid repositories and Worktrees, supporting `.git` files/directories, then ask which to add. Stop descending inside a valid repository, so nested repositories/submodules are not added implicitly. Do not follow directory links or Windows junctions or enter `.git`. Show directories scanned/repositories found and allow cancellation without adding anything. Skip invalid/inaccessible directories, summarize them, and log details. Duplicates are not registered twice; batch additions save/notify once, preserve the active repository/layout/drafts, and remember additions for reopening. Discovery runs only on explicit directory addition.

The top-level Repositories list groups main/linked working directories by shared Git storage into one logical entry named from Git's main working directory. Discovery/add/existing counts use logical repositories; independent clones stay separate. Switch directories under Worktrees; activating a linked directory still marks the logical repository, and actions target the active directory. Adding only a linked Worktree preserves its entry; without an active choice, prefer a registered main directory.

Repositories has one Add… plus and Refresh; its title menu shares Add. The embedded Add dialog switches between Add Repository and Add Group, defaulting to repositories. Group creation accepts a name for an empty group, validates blank/long/duplicate names inline, supports Enter/Escape, and uses no native input box. Switching modes preserves their drafts and completed scan choices, cancels an ongoing scan, and closing cannot partly add. Only choosing a disk directory uses VS Code's native picker. The same dialog then shows cancelable scanning and name-sorted logical repository choices marked addable or disabled/already added. Addable items initially select all and support filtering, select-all, toggles, and Shift ranges. Destination group and inline group creation share confirmation, whose primary button states the addition count. Only final confirmed items register; scan/filter/close do not change the catalog, and skipped reasons remain inspectable. Repository/group titles have management menus; single/multiple repository menus offer Remove from AlwayGit… with an embedded list and explicit disk-preservation explanation. Removal deletes navigation/persistence, releases watchers, and prevents immediate rediscovery; it does not delete directories/Git data. Explicit re-add restores display.

Create, rename, delete groups and move one/multiple logical repositories into them. Groups are collapsible; ungrouped repositories sit directly at the root. Deleting a group appends its repositories to the root in their existing order without unregistering them. Names, assignments, and ordering are shared with paths in one VS Code Profile/runtime. Root groups/repositories share an order; new/moved entries append to their destination, renaming keeps position. Same-level drag sorting shows insertion lines; Move Up/Down disable at boundaries. Legacy migration retains original root repository order, then saved group creation order. Sorting/migration preserve IDs, active Worktrees, drafts, and selections; Shift follows expanded visual order.

Single-click a repository/Worktree changes operation selection only; Ctrl/Cmd toggles, Shift selects a range, Ctrl/Cmd+Shift adds a range. Double-click or Enter activates it. An ordinary repository switch selects/scrolls to Working Tree and shows current changes rather than the last Commit. Startup, reload, and tab restoration restore saved Graph/Commit state; explicit cross-tab Commit/comparison requests open their specified targets. Right-click selection keeps the bulk set; right-click another item selects it alone. Repositories, Local Branches, each Remote, Tags, and Worktrees are mutually exclusive sidebar operation scopes: a nonempty selection clears other blue operation selections. Current repository has a theme-accent repository icon without an extra triangle/column. Current Worktree/local branch uses a solid play triangle (black on light, white on dark) with aligned empty space elsewhere. Blue indicates operation selection independently of current status. Branch Graph checkboxes precede the triangle and branch icon. Scope changes do not change active repository/branch/Graph filters. `aria-current` exposes current status without a redundant Current badge; Detached HEAD has no marked local branch but retains its Worktree marker.

Sidebar row backgrounds indicate temporary operation selection; a thin outline indicates actual focus. The current repository also has a bold name and its independent repository icon. Clicking list whitespace or pressing Escape clears selection and range anchors while retaining the last row focus outline. Clicking or moving focus to another region clears sidebar selection and its row outline. Independent group, expansion, and Graph controls clear unrelated selection; reorder controls, item menus, and confirmation dialogs retain their captured targets and restore focus on cancellation. Escape in a menu first closes it; Escape back in the list clears selection. Clearing operation selection never changes the actual repository, branch, Graph checkboxes, or displayed details. Hover, scrolling, and background refresh retain selection. Window blur hides outlines and clears temporary selection unless a menu, modal, or drag owns the interaction.

Global shortcuts require Webview focus and target the active repository/Diff, not sidebar action selection or hover. Single keys default on and follow the manuals' selection/shortcut reference; tooltips show active bindings. Capture-phase dispatch avoids stopped bubbling. Inputs, editable content, selectors, IME composition, dialogs, and menus take priority; held keys do not repeat actions. Clicking noninputs transfers focus. Shortcuts reuse button callbacks/availability. C opens Commit; A/U confirm filtered split-list scope, but full repository in unified mode. Diff navigation expands a collapsed dock before following its active navigation mode.

General → Keyboard shortcuts provides search, categories, modified-only filtering, replacement recording, up to two bindings, removal, disable, and per-action/all defaults. Store only overrides in user `alwaygit.interfaceSettings`; missing uses defaults and an empty array disables. Applied settings synchronize windows in the same configuration environment; old session preferences are migration input only. Ctrl/Cmd adapts to platform. Conflicts, including default restoration, require explicit reassignment. Basic navigation/selection keys are reserved; multi-step chords and full VS Code/OS conflict checking are unsupported. Old sessions default to no overrides while retaining their single-key switch. Apply persists; Cancel restores; recording Escape only cancels recording. Drafts/views/layout stay intact. Turning single keys off suspends unmodified and Shift+printable bindings, keeping other combinations; Ctrl/Cmd+R can be changed/disabled. Tooltips, accessible keys, and help share configuration. The separate VS Code New Embedded Terminal binding uses native shortcut settings.

Ctrl/Cmd+A in a multiselect region, heading, or inline control selects its own scope and makes it the sole sidebar operation scope; Escape clears only that scope without activating another. Region capture prevents whole-page text selection. Repositories selects all logical entries; Local Branches all local branches; each Remote only its branches; Worktrees all current-repository directories; Tags only local Tags, excluding remote-only Tags from bulk operations. These controls never change Graph `checkedRefs`. History selects only loaded real commits without implicitly loading pages or including Working Tree. File scopes include only visible files. Inputs/editable content retain native select-all/Escape behavior.

File selection and Diff are independent. Ordinary click selects only that entry and changes Diff; Ctrl/Cmd toggles, Shift ranges, Ctrl/Cmd+Shift adds ranges, select-all, and Escape retain the current Diff. Row backgrounds indicate action selection, survive hover, and disappear immediately on deselection. A small dot beside the file icon and `aria-current` identify the preview; keyboard focus uses a fine outline. Unified staged/unstaged versions of one path select/mark separately.

Changed Files in split/unified Working Tree, Commit Details, and Commit comparison clears selection and range anchors on list-whitespace clicks while retaining the previous file row focus outline. Clicking or focusing outside the file-operation region clears both selection and its outline. File icons and row padding act like the filename. The current Diff and its small icon marker remain independent. Path filters, Copy Paths, group actions, file menus, and confirmation dialogs retain the required selection; filtering and collapsing still reconcile it against visible files. Right-clicking any part of a file row focuses its filename before opening the menu and restores that focus when the menu closes.

Neutral file icons carry colored Git corners: yellow M, green A, red D, purple R, ? untracked, ! conflict, C copy, T type change. Hover supplies meanings without a permanent legend.

Working Tree filters filenames/full relative paths live, case-insensitively, across all groups. Search persists per working directory in instance memory across refresh/views but clears when reopening. Show matched/total counts, retain zero-match headings, and explain hidden conflicts/current Diff; summary/Commit always use complete repository state. Split group actions use all files without a filter and matched paths with one, independent of bulk selection. Stage/Unstage confirm actual counts with initial confirmation focus (Enter executes; Escape/backdrop/Cancel cancels). A/U share that scope. Unified toolbar actions/A/U always target all. File-menu Stage/Unstage affect visible selection without another confirmation. Grouping applies to additions/restoration/discovery, preserving saved paths, working-directory IDs, individual drafts/views, without merging Worktree file/Index state.

Commit… remains next to Unstage in Staged even when empty, collapsed, or filtered out. The toolbar and C open the same centered dialog with repository, branch, candidate files, and Message focus. Ordinary entry initially lists/checks all Staged files; deselected staged content remains. Unified Commit Selected lists only the selected paths, allowing checks within that list. Deduplicate paths: selecting an unstaged version uses latest saved disk content and stages it; selecting only a staged version commits Index content and retains unstaged changes. A path with both versions is marked combined, with an explanation that both are included. Rows show checkbox, relative path, and source; long paths ellipsize with tooltips, and more than about six rows scroll internally.

Opening/canceling Commit does not change Index. Execution uses an independent Index, updating only selected paths after success and preserving others. Git hooks/signing still run; hooks may format selected files. A final candidate containing out-of-scope changes is rejected before HEAD updates and retains the original Index, without promising rollback of hook disk edits. During an active Git operation, Commit Selected is unavailable and ordinary Commit cannot deselect files, using full staged-result review. Empty draft/no staged files/conflicts still permit opening and saving a draft; ordinary execution needs a nonempty message, a staged file, and zero conflicts. Enter inserts a line; Ctrl/Cmd+Enter submits, excluding IME/repeat. Amend starts off; only an empty draft reads HEAD's message, and cancellation/late reads cannot overwrite new text. Cancel/Close/Escape/backdrop retain and immediately save the draft and restore focus. Failure retains dialog/draft; success closes and clears only this repository's used, unmodified-since-submit draft. Active operations reuse staged review without overlapping dialogs.

Local/remote branch names form recursive `/` directories, such as feature > login > api. Expanded state persists per repository; first opening/Checkout expands the active branch path. Initial scope selects current local branch/upstream. Multi-ref history is the union of reachable commits with shared ancestors once. Empty scope has an explanatory empty state, while ordinary history always retains Working Tree with its current branch, without restoring filtered HEAD. Locate HEAD selects/scrolls already-loaded HEAD while preserving Graph/search/refs/pages; only a missing HEAD restores necessary filters and performs bounded reads, continuing unfilled pages. Repeated clicks relocate. Branch badges/accessibility identify visible HEAD.

Locate Tag Commit / Locate Branch Tip in Graph similarly select/scroll loaded targets; missing targets switch to that ref's history, clear search, and start at its Commit under the same read limits. An eye marks Tags in the current scope; loading marks requests. Failed new-scope reads prohibit appending pages to the old Graph until retry.

There is no separate permanent location panel. Sidebar/toolbar/rows/details/summary carry repository, Checkout, object, Working Tree, and loaded counts. New-scope loading retains the old Graph, shows the requested scope in its summary, then a failure/retry there if necessary. Identical ref sets do not reread/reset position. A persistent Back icon before search restores the previous successful scope, search, object, and reading position while canceling pending reads. A target icon appears only for search or non-current-branch scope and clears search, scopes to current branch (HEAD if detached), and locates HEAD; it is separate from scope-preserving Locate HEAD. In-memory history keeps at most 12 views per repository across 8 repositories; a view over 10000 commits stores context only, and other views over 24000 total evict oldest records. Changed refs/HEAD or uncached deep history reread the scope and return to its first screen.

Single-file menus offer Show File History for Working Tree, Commit Details, comparisons, and Stash files; multiple pathnames omit it. History retains checked refs and clears message search. A path bar identifies the file and ref scope, with icons to include all local/remote-tracking branches or exit. Selecting a record automatically chooses its historical pathname and a suitable real Merge Parent, while details retain the complete Commit. File history follows Git-detected renames along each merge Parent, excludes independent same-name recreations after deletion, and retains only related commits. Dashed edges represent ancestry across omitted intermediate commits. Working Tree appears only for target changes; its list and split group actions use that file scope, while repository summaries, ordinary Commit, and unified toolbar bulk actions retain their existing scope. Exit clears only the file condition; Back restores refs, search, file, viewed object, and position. The per-repository persistent file condition participates in paging, refresh invalidation, caching, and stale-request isolation. Empty results and read failures are explicit; failures retain the old graph and block appending its old pages. Locate in full history clears file and message filters before locating the target.

Message search waits 200 ms after typing. The adjacent filter icon opens advanced author name/email, inclusive UTC committer dates, literal repository-relative file/directory, single-line added/removed code (literal or Git ERE), and unique Commit ID fields. Advanced fields remain drafts until Apply; applied conditions, message, and selected refs combine with AND over the whole history, paging matching commits. Code plus path restricts the same path's diff; absent a path, ordinary history permits any changed file, while file history restricts code to the identity's per-commit historical paths, including rename sources, queried in grouped batches. Dates explicitly use UTC; rows label the author date. Paths do not expand wildcards. Dedicated file history retains rename tracking and intersects matches. Protocol fields are structured, never arbitrary Git options; IDs require 4–64 hexadecimal characters resolving to a commit. Code inspects each Merge parent's diff, then deduplicates OIDs before paging. Advanced queries collect complete matching IDs with an 8 MiB output bound; exceeding it fails visibly without publishing partial results. Metadata reads cover only the current page. Stop, condition changes, and repository switches cancel old requests. Applying new conditions immediately clears rows and blocks cross-condition append. Conditions persist per repository and Back view with compatibility for old sessions. Results show loaded counts and + for another page, hide Graph, and retain badges, author date, selection/menu, and publication markers. Locate in Full History clears message, advanced, and file conditions within the same refs, reads at most 20 pages or 10000 commits, then retains loaded results with continue/narrow-scope guidance. Clearing all search conditions restores Graph and widths.

More → Open Repository Folder retains the outlined folded-folder/VS Code corner icon, near-black on light and foreground-colored on dark/high contrast. It shows its label and full-path tooltip, explaining Explorer behavior when already in this window. Prefer an existing project window for the actual directory, otherwise open a new project window while retaining the Workbench window. Matching supports multiroot workspaces, distinguishes Worktrees, and prefers the most recently active matching window. A current-window match opens Explorer and uses native commands to reveal the directory/ancestors/files; reveal failure keeps Explorer open without substituting a file-open action. A single-root exact match says the current window is already at the repository; an enclosing/multiroot match says it is in this workspace. ## Git LFS

The toolbar More menu, repository menu, and file menu open the Git LFS panel. On demand it shows the host version, filter configuration, indexed object IDs and sizes, working-file state, and local cache state. Status reads never contact the network. The list is limited to 1,000 entries; pending uploads are local candidates and do not verify remote object availability.

Explicit operations fetch the current commit or selected objects, restore cached content, download and restore, upload current-branch objects, and preview/apply root `.gitattributes` tracking changes. Network operations bind the selected remote, captured effective destination configuration, and reviewed commit. Changes require a refreshed review. Restore uses Git LFS protection for modified files; tracking edits remain unstaged and do not migrate history. A missing Git LFS installation produces host guidance without installing tools or changing global configuration.

Historical Diff, commit-tree previews, and native text Diff can read local LFS objects. Content is verified against SHA-256 and size before use, with a 32 MiB text limit per side and the existing 4 MiB image limit. Any unresolved side produces a placeholder for the whole comparison. Download requires explicit remote selection and confirmation, fetches only the fixed commit/path object into the cache, and refreshes the same preview without checking out a commit or restoring working files. Isolated previews do not offer downloads. Migration, cache pruning, and LFS locks remain outside scope.

## Reflog and recovery

The top More menu opens a separate Reflog dialog for the current worktree HEAD or a local branch. Entries show Git's original description, event time, actor and full commit ID. Inspect commits, merge parents and file diffs independently of the main Graph, File History and drafts. Bounded snapshots expire after ten minutes and page through at most the latest 5,000 entries; new records do not shift loaded pages. Refresh captures a new snapshot. Git reads support linked worktrees; unavailable objects report an error.

Recovery binds the full selected OID and creates a named branch without switching by default. Switching requires the explicit checkbox and uses existing branch validation and write queues. Rebase recovery references have their own list. Reflog does not recover discarded uncommitted files.

## Feature and environment boundaries

Git runs on the repository's extension host; architecture targets local, WSL, Remote SSH, and Dev Containers. Actual evidence is in [validation boundaries](VALIDATION.en.md#validation-evidence-and-boundaries). Untrusted workspaces do not run Git; browser-only virtual workspaces are unsupported.

Whole-file/Git-hunk staging, ordinary and interactive Rebase, commit reordering and Squash/Fixup are supported. Format Patch, remote Tag replacement, and freely floating panels are outside scope. Single/same-Remote bulk branch deletion, explicit Tag Push, and lease-protected remote Tag deletion are supported; see [operation restrictions](#disabled-and-blocked-operations) for confirmation/partial failures.

Diff compares complete text read-only without line truncation, failing at resource limits. Supported images preview; other binary explains its status. Images/binary provide neither native editing nor Diff. Read limits/sources are in [Diff and native editors](ARCHITECTURE.en.md#diff-and-native-editors).


## Interactive Rebase

Current local branch and commit menus open a linear plan on a fixed base. The branch entry defaults to up to 20 recent unpublished commits; the commit entry includes the selected commit. Ranges allow up to 500 commits and reject roots, merges, dirty worktrees and active operations. Edit pick/reword/squash/fixup/drop oldest first, reorder with drag, buttons or Alt+arrows, and inspect files independently. Every original commit appears exactly once; removal requires explicit drop. Squash/fixup need an earlier retained commit; reword/squash require a complete nonempty message.

Plans bind the worktree, branch, HEAD, base and a fifteen-minute expiry. Execution rechecks identity and remote reachability. Locally cached remote-reachable commits need explicit risk acknowledgement; no automatic Fetch or Push occurs. Original HEAD is retained as a Reflog recovery ref. Pauses show progress, conflicts/empty/review state and recovery ref. Empty commits have explicit keep/skip controls; skip requires confirmation. Continue, skip and abort recover after reload. Invalid saved plans or helpers disable continue and skip.

Skip is disabled when replay already created the commit but message editing failed; Continue retries the reviewed message, or Abort restores history. An internal checkpoint failure disables Continue and Skip; abort and prepare a new plan.
